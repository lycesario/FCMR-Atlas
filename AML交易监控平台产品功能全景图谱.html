00怎么读这份图谱

这套产品的本质是：在交易发生的 100ms 内，把多源数据、规则、图卷积与对手方筛查收敛成一个可解释、可举证的风险判定，并贯穿到告警处置与监管报送。

四层结构

层级这一层包含什么产品本质
第1层（d1–d4）：实时监测与处置底座d1 实时流式监控、d2 规则引擎、d3 交易对手方筛查、d4 告警分级与案例管理把'看得到风险'变成'拦得住风险'的实时闭环
第2层（d5–d9）：识别与智能d5 大额报告与CTF、d6 行为模式检测、d7 GNN图卷积、d8 意图推理、d9 跨链溯源从单点阈值走向序列、关系与意图的多维识别
第3层（d10–d14）：治理与实体d10 误报治理、d11 实体解析、d12 情报融合、d13 制裁筛查、d14 KYC关联把噪声压下去、把实体串起来，让风险可归因
第4层（d15–d18）：数据与合规底座d15 数据分层、d16 审计留痕、d17 监管报送、d18 可观测让一切判定可回放、可审计、可报送
三条先决判断：
1. 必须先有数据分层与宽事件底座，否则跨账户图查询与 100ms 判定无从谈起；
2. 必须先冻结制裁名单与规则版本口径，否则回放、审计、报送全部失真；
3. 必须先具备可解释与留痕能力，否则监管不采信、抗辩必败。
一条死亡陷阱：用'告警数量'当成功信号。2300+ 每日告警里绝大多数是噪声，告警越多往往说明误报治理越失败，而非风控越强。

六个核心对象

对象定义为什么不能错
交易（Transaction）一次链上或平台内的价值转移事件，含对手、金额、时间错判会把分层洗钱当正常业务，放行被盗资金
地址（Address）链上价值容器，约 99.2% 无实名关联误标会让高危对手被当普通地址放行
实体（Entity）由多地址/账户归并出的统一主体不归并会让一人多身份风险分散、低估
警报（Alert）满足规则/模型触发的待处置信号错分级会让真实风险淹没在疲劳中
案例（Case）合并去重后的可处置调查单元不合并会让一个案件拆成数十工单
报送（Filing）SAR/CTR/旅行规则等监管报文错报文会被退回甚至构成违法

国际市场

三条最常被低估的合规红线：
1. 提币前对手地址扫描——滞后一步资金即不可逆；
2. 名单零空窗更新——刚制裁地址被放行就是违法；
3. 7 年留存与不可篡改留痕——缺证据即抗辩失败。

09如果要做，从哪开始

链路长、环节多，冷启动的关键是用一个场景把主线跑通，再放大。

收敛步骤
  • 第一步：搭建数据分层与宽事件底座（热温冷冰+ClickHouse）
  • 第二步：落地 100ms 流式判定与规则引擎热更新
  • 第三步：接入对手方筛查与制裁/混币器拦截
  • 第四步：用 GNN+意图推理提升识别、用回测+标注治理误报
  • 第五步：打通告警案例管理与 SAR/CTR 报送闭环
候选路径
  • 路径 A：实时流式判定即服务（Kafka+Flink 托管）
  • 路径 B：GNN 风险传播分值 API 喂规则
  • 路径 C：误报治理与规则市场（回测+标注）
  • 路径 D：执法/机构链上溯源（CN 合规场景）
四条路径的共同点：都先把'可解释、可回放、可审计'作为第一资产，再谈智能与规模——不可举证的能力在监管面前等于零。
