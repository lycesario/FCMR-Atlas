DID 数字身份平台的本质，是把「你是谁」从平台账户还原为你自己可携带的密码学事实。全网 18 条 DID 标识符背后，真正的竞争不是发证速度，而是撤销时效、密钥恢复率与跨体系互认这三件没人愿意先做的事。谁先让身份丢不了、销得掉、认得出，谁才拥有身份基础设施的定价权。

00怎么读这份图谱

这套产品的本质主线是：把 W3C DID 标识符、DID 文档与可验证凭证三组件，组装成一张「签发—持有—验证—撤销」全链路可运营的身份网络。它的价值不在发证，而在两件事：让验证便宜到可以实时进行，以及让撤销快到被盗身份无处可逃。锚定层（IPFS/Arweave/链上）只是成本-持久性的权衡工具，不是卖点。

四层结构

层级这一层包含什么产品本质
第1层（d1–d5）标识与锚定层DID 方法体系、DID 文档、密钥管理与恢复、通用解析器、去中心化锚定存储这一层的产品本质是身份的「户籍与地契」：方法选型即终身国籍，密钥恢复率决定身份能否活着
第2层（d6–d10）凭证与信任层凭证签发、验证与撤销、选择性披露与 ZK、信任注册表、钱包交互这一层的产品本质是把信任变成可携带资产：最小披露+可撤销是合规与隐私的双重底线
第3层（d11–d14）互操作与合规层跨方法跨链互操作桥、链上 KYC、女巫防御与人格证明、监管报告与审计这一层的产品本质是翻译与守法：在标准碎片化和监管硬约束之间架可审计的通道
第4层（d15–d18）应用与生态层企业 IAM 集成、AI Agent 机器身份、身份图谱洞察、生态治理与开放协议这一层的产品本质是规模变现：把身份能力卖进存量 IAM、机器经济与数据洞察市场
先决判断一：密钥恢复体系必须先于签发存在——没有恢复的身份系统签得越多，未来作废与客服灾难越多。
先决判断二：撤销机制与状态列表必须先于商业模式存在——不可撤销的凭证卖给谁都是定时炸弹。
先决判断三：信任注册表与签发方治理必须先于生态扩张存在——先放水后治理的注册表会永久贬值。
最容易误当成成功信号的死亡陷阱：签发量暴涨。如果签发的是无撤销机制、验证强度不明、跨体系无人认的凭证，量越大说明补贴越狠、信任池污染越快——真实信号是「验证成功率×撤销时效×跨体系互认率」，而不是签了多少张。

09如果要做，从哪开始

链路长、环节多，冷启动的关键是用一个场景把主线跑通，再放大。

收敛步骤
  • 第一步：冻结 DID 方法选型与密钥恢复模型（自托管/MPC/云 KMS 三选一并做恢复演练），这是产品地基，返工等于重来
  • 第二步：跑通最小凭证闭环——一个高信任签发方、一种凭证、一条五步验证链+状态列表撤销，先证明「签得对、验得动、销得掉」
  • 第三步：接一个法定强制场景（EUDI 组件、交易所合规白名单或企业员工凭证），让收入来自监管时间表而非概念买单
  • 第四步：铺信任注册表与互操作桥，解决「凭什么信你签的」与「别的体系认不认」两个扩张瓶颈
  • 第五步：沉淀身份图谱与审计能力，向风控方与监管侧输出数据服务，完成从工具到基础设施的位置跃迁
候选路径
  • 路径 A（合规组件商）：只做链上 KYC 徽章与白名单准入，对接持牌交易所与 DeFi 机构池，按验证次数与席位收费，轻资产快回款
  • 路径 B（EUDI 生态供应商）：对齐 eIDAS 2.0 规范做钱包/签发/验证组件，吃成员国强制时间表的政府采购预算
  • 路径 C（企业 IAM 桥）：做 OIDC/SAML 与 DID 双栈桥接+员工凭证+Agent 审计网关，从存量企业安全预算里切份额
  • 路径 D（协议网络方）：做撤销聚合网络或跨体系解析层，向全行业按查询收费，慢但天花板最高
四条路径的共同点是：都要求「可验证的撤销时效」作为第一资产——无论卖给监管、交易所、企业还是网络节点，客户买的核心都是「这张身份出事时你能多快让它失效」，其余能力都建立在这个可举证的承诺之上。
