全球监管规则正以 18 个司法辖区、216 部法规的速度膨胀为不可人工阅读的知识洪流——同一笔跨国资金，在美国要冻结、在新加坡要披露、在韩国要拒绝。监管图谱平台把散落的法规与制裁名单结构化为可计算的知识库，用规则引擎在 100ms 内给出带条款引用的三态判定，让每一条合规结论都可解释、可复现、可审计。从 Chainalysis 到 TRM Labs，合规知识库正在成为数字资产的入场券而非成本项。

00怎么读这份图谱

这套产品的本质是把全球监管规则变成一台可计算的判定机器：法规知识层把条款结构化，规则执行层把知识变成毫秒级判定，报告与证据层把判定变成监管可见的合规证据。它的价值不在功能数量，而在每条结论都能回链到法规版本与数据版本的不可抵赖证明。

四层结构

层级这一层包含什么产品本质
第1层（d1–d5）法规知识层法规知识图谱、辖区规则矩阵、牌照地图与准入、规则变更管理、监管分类学本体把散落在各国公报与律所网页里的规则，变成有版本、有溯源、有辖区的可计算知识
第2层（d6–d10）规则执行层规则引擎、地理围栏与制裁筛查、交易监控规则库、实体风险评分、冲突校验与死锁检测把知识变成 100ms 内可解释的判定，多套规则并行叠加而不冲突、不卡死
第3层（d11–d14）报告与证据层监管报告自动化、Travel Rule 数据交换、SAR 管理与审计留痕、影响分析沙盒把判定变成监管可见、时限可控、历史可复现的合规证据链
第4层（d15–d18）智能演进层监管情报融合、AI 调查协作、误报治理与规则调优、合规即服务 API让整个体系自我更新、自我解释，并把知识资产以 API 形态商业化
三条先决判断：① 覆盖 18 个辖区的法规图谱与版本管理必须先于任何判定功能存在——没有可溯源的知识底座，所有判定都是不可审计的黑箱；
② 规则版本化与数据版本双留痕必须先于第一个客户上线——事后补留痕等于没有留痕；
③ 制裁名单分钟级更新通道必须先于获客——名单时效是这类产品被采购的第一理由。
死亡陷阱：把「告警量上去、拦截率好看」当成产品成功。最大宗罚款（如 Block 1.2 亿美元）恰恰来自筛查失效与 SARs 积压——只会产生告警却不能给出可解释、可复现、带条款引用结论的平台，只是在批量生产合规噪音，调查积压越高，客户离监管处罚越近。

六个核心对象

对象定义为什么不能错
规则（Rule）由法规条款翻译而来、带版本与生效期的可执行判定单元规则与条款引用断链，整个平台的判定在监管问询中不可信
辖区（Jurisdiction）一套独立立法与执法体系的最小规则作用域辖区归属判定错误会套用错误法规，跨境业务的三态判定全盘失真
规则矩阵（Rule Matrix）司法辖区×资产类型×业务行为的三维判定索引矩阵空白格默认放行是最大隐性违规源，漏一格就是漏一类业务
三态判定（Tri-State Verdict）同一事件在不同辖区分别给出冻结/披露/拒绝及条款依据的结论只给单态结论无法支撑跨境业务，且冲突结论必须有仲裁留痕
规则版本（Rule Version）不可变、带生效时间轴与变更审批记录的规则快照覆盖式更新让历史判定失据，SAR 复核与监管复查时无法自证
false_positive_rate按规则/客群/时段多维拆解的误报率（0.002 级目标）只看总误报率找不到治理抓手，误报失控即调查积压即罚款

09如果要做，从哪开始

链路长、环节多，冷启动的关键是用一个场景把主线跑通，再放大。

收敛步骤
  • 第一步：先做法规图谱与版本管理（覆盖主要辖区的可溯源知识底座），再谈判定与 API
  • 第二步：以制裁筛查+地理围栏单点切入，用名单时效 SLA 与阻断证据留痕拿到首批标杆客户
  • 第三步：上规则引擎与冲突校验，把 MiCA/MAS/FinCEN 三套规则并行叠加跑通三态判定
  • 第四步：补齐报告自动化与 Travel Rule 交换，形成从判定到证据的完整闭环
  • 第五步：开放筛查/图谱/判定 API 与私有化双轨交付，把知识资产变成可规模化订阅
候选路径
  • 路径 A：数据订阅先行——先卖牌照地图与监管情报订阅，用轻产品建立客户关系再上重判定
  • 路径 B：旗舰 API 先行——直接以跨辖区三态判定 API 打跨境交易所，用最难场景立壁垒
  • 路径 C：执法侧先行——从公安/FIU 取证溯源切入，用真实案例反哺图谱再转向商业合规侧
  • 路径 D：报告工厂先行——从报告自动化外包切入，用按件计费现金流养图谱与引擎建设
四条路径的共同点：第一资产都是「带版本与条款引用的可计算法规图谱」——没有这个底座，API 站不住、订阅没壁垒、案例不可复用、报告不可复现。
